# 三、HelixWM Final 的目标架构

## 3.1 双链状态定义

重新明确两条链的数学定义。

### Real Strand

Real Strand 表示当前真实环境状态及其基于历史观测形成的状态估计。

定义：

z_t^R = (h_t^R, s_t^R)

其中：

- h_t^R：确定性隐状态。
- s_t^R：随机隐状态。
- o_t：当前真实观测。
- a_t：执行动作。

在正常观测条件下：

z_t^R = Posterior(z_{t-1}^R, a_{t-1}, o_t)

缺少观测时：

z_t^R = Prior(z_{t-1}^R, a_{t-1})

但必须区分预测状态和真实观测支持的后验状态，不能把缺帧期间的预测结果标记成真实观测。

### Dream Strand

Dream Strand 表示从 Real Strand 出发形成的未来预测轨迹。

定义：

z_{t+k}^{D,i}

其中 i 表示第 i 条候选未来轨迹。

Dream Strand 应当能够：

1. 从当前 Real 状态初始化。
2. 沿未来动作序列持续演化。
3. 形成多条可能的未来轨迹。
4. 记录每条轨迹的不确定性。
5. 接收 Real Strand 的周期性校正。
6. 在新观测到来时重新评估预测。

明确 Real 与 Dream 之间的信息流，不能只通过复制 latent state 实现表面上的双链结构。

## 3.2 双链协同机制

设计一个明确的 Cross-Strand Correction Module。

它至少需要处理：

- Real → Dream：真实状态约束未来预测。
- Dream → Real：经过置信度检验的预测信息辅助真实状态估计。
- Dream → Dream：候选之间的预测差异和一致性分析。
- Real → Real：新观测到来后的状态校正。

注意：

Dream 对 Real 的反馈不能直接覆盖真实观测形成的后验状态。

必须采用有约束的融合机制，并区分观测支持与模型推断。

需要给出：

1. 模块数学表达。
2. 输入输出张量维度。
3. 梯度传播方式。
4. 参数共享方式。
5. 是否需要独立校正网络。
6. 时间复杂度和显存开销。
7. 与原始 RSSM 的兼容关系。

优先采用最小必要改动，不要无理由重写 DreamerV3 的学习骨干。

## 3.3 多候选未来轨迹

重新设计 candidate system。

每条候选轨迹应记录：

- latent state。
- action sequence。
- predicted observation。
- reward prediction。
- termination prediction。
- model disagreement。
- uncertainty。
- prediction error。
- confidence。

不要简单地把候选数量从8增加到32或64。

必须研究候选数量、预测深度与计算成本之间的关系。

设计候选筛选机制，使其同时考虑：

1. 预测准确性。
2. 不确定性。
3. 候选之间的多样性。
4. 长时程累积误差。
5. 任务奖励。
6. 控制风险。

不能仅仅选择相对评分最高的候选。

如果全部候选都不可信，必须允许系统拒绝使用候选结果。

## 3.4 动态不确定性管理

设计显式的不确定性估计机制。

至少研究：

- Ensemble disagreement。
- Latent predictive variance。
- Observation reconstruction error。
- Temporal prediction error。
- Candidate ESS。
- Model calibration。

需要区分：

- Aleatoric uncertainty：环境本身的不确定性。
- Epistemic uncertainty：模型知识不足造成的不确定性。

设计动态控制机制：

当不确定性较低：

允许正常预测和任务控制。

当不确定性中等：

增加观测检查频率，限制预测深度。

当不确定性较高：

进入保守动作模式。

当不确定性超过可信范围：

拒绝高风险候选，执行预先定义的回退策略。

阈值必须通过独立校准集确定，并在测试前冻结。

禁止根据最终测试 seed 单独调整阈值。

## 3.5 长时程缺帧机制

现有 V2 最多维持5步候选，需要重新设计。

研究以下方案：

- 固定长度候选维持。
- 动态长度候选维持。
- 基于不确定性的预测深度调整。
- 多尺度时间预测。
- 周期性 Real–Dream 校正。
- 低置信度下的保守控制。

需要比较不同策略在 gap 1、5、10、20、50、100 下的表现。

不允许简单地无限延长候选轨迹。

需要明确：

1. 长缺帧期间的状态误差如何累积。
2. 何时停止信任预测。
3. 如何控制候选退化。
4. 如何避免错误预测持续反馈。
5. 如何在没有新图像时保持控制稳定。

## 3.6 观测恢复与双链重连接

这是 Final 架构的重点。

当真实图像重新出现时，不允许直接将最高评分候选覆盖 Real。

设计专门的 Reconnection Module。

流程至少包括：

1. 接收恢复后的真实观测。
2. 计算 Real 与 Dream 的预测差异。
3. 检查候选状态可信度。
4. 评估候选与恢复图像的一致性。
5. 进行 posterior correction。
6. 重新初始化或更新 Dream Strand。
7. 恢复正常策略控制。

必须避免重复推进同一个 action。

需要比较：

- 直接使用 prior。
- 直接选择最佳候选。
- 恢复首帧 posterior fusion。
- 带置信度约束的双链重连接。

必须记录恢复后状态误差、奖励变化和重新稳定所需动作数。
